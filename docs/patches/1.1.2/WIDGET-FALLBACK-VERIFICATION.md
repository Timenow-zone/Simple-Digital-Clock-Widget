## Воспроизведение до исправления

На точном `977c5603…` созданы независимые новые fixtures. Браузер подтвердил прежние результаты: Site Admin в двух сайтах multisite получает **22/103 невалидных блока** после widget save; на WP 6.3.2 / PHP 7.0.33 **три HTML-only caption** меняются на буквальные entities в редакторе после title-only update.

Новый PHP-набор до правки дал **154/230**: он проверяет DOM-подпись, исходный JSON, повторное сохранение, KSES и сохранность отсутствующего caption при title-only update. Отдельно проверены реальные REST permissions: Editor/Author получают 403, Site Admin может сохранять виджеты, но не имеет mapped capability `unfiltered_html`.

## Исправление

**Виджеты.** Подготовка entities и финальное кодирование CR/Unicode вынесены в общие функции для unslashed HTML. Post pipeline использует их с прежней обработкой slashes. Для стандартного `WP_Widget_Block` добавлен ранний `widget_update_callback`: он берёт исходный unslashed input, подготавливает caption, повторно выполняет **штатный `wp_kses_post()`** и кодирует результат. HTML продолжает проходить обычные allowlist, CSS/URL callbacks и фильтрацию опасных атрибутов.

Обработчик сохраняет отказ `false`, другие настройки instance, поведение чужих классов виджетов и unfiltered users. Если предыдущий callback уже заменил content, его результат остаётся приоритетным. Последующие callbacks также могут изменить или отклонить сохранение.

Этот дополнительный контракт проверен до включения защиты: промежуточный `982aafd4…` давал **46/47**, перезаписывая раннюю замену содержимого. Окончательный ZIP даёт **47/47** на всех десяти контекстах. Промежуточный ZIP и RED evidence сохранены; он не является кандидатом к выпуску.

**Caption только в HTML.** PHP больше не синтезирует отсутствующий JSON caption через зависящий от Core/PHP декодер. Исходный HTML остаётся источником подписи; уже существующий браузерный `blocks.getBlockAttributes` fallback читает его с правильной DOM-семантикой. Явно заданный JSON сохраняет прежний приоритет. Восстановление отсутствующего timezone не менялось. При полном сохранении Gutenberg сам сериализует caption в JSON; новые тесты проверяют этот переход и стабильность повторного save.

Нового декодера HTML5, миграции БД, массового изменения записей или изменения формата существующего JSON нет. Standalone-виджет 0.7.0 и его bundle не менялись.

## Уточнение прежнего security fixture

Первый общий прогон дал по одному отрицательному утверждению на девяти контекстах. Старый тест `plain-text caption JSON cannot break a block comment` подавал **только HTML caption**, а затем требовал, чтобы PHP добавил caption в JSON. Это требование противоречит новому сохранению необязательного HTML-only поля и не проверяет сохранность изначального JSON.

Вход fixture уточнён: опасная строка `--><script>…</script><!--` теперь явно передаётся как JSON caption через штатный serializer. Утверждение не ослаблено: оно по-прежнему требует исходную строку в JSON и отсутствие настоящего script-тега. Количество **464** прежних проверок сохранено. Уточнённый набор отдельно прошёл **464/464 на точном `977c5603…`** и на окончательном кандидате. Подписи только в HTML покрыты самостоятельными PHP и браузерными проверками, включая отказ от синтеза JSON при title-only update.

Исходные отрицательные результаты и первое общее выполнение сохранены. Они не включаются в итоговый GREEN вместо повторного запуска с уточнённым входом.

## Обновление и откат

Официальный **1.1.1 → окончательный 1.1.2 → save → официальный 1.1.1 → тот же окончательный 1.1.2** проверен без восстановления БД. Для native Local baseline действительно создан на 1.1.1; до первого candidate save отдельно проверены исходные 14 файлов и неизменность всех трёх raw posts после замены ZIP.

В окончательном общем цикле физически заменены **девять установок / десять контекстов**, включая LocalWP и multisite. Каждый раз сверены 14 файлов официального 1.1.1 и 15 файлов кандидата. Старый редактор во всех трёх движках принимает новые сохранения, включая подписи виджетов. Проверены и повторное обновление, и сетевая/отдельная активация multisite.

Все **17 366 строк post_content и 96 widget contents** сохраняют хеши при откате, чтении старой версией, повторном обновлении и чтении кандидатом. Основные 20 ID сверяются с сохранённым raw content напрямую. Чтение не выполняет пересохранений. БД не сбрасывается и не восстанавливается.

Граница совместимости: блоки с непустым caption только в HTML уже не были валидным нативным форматом 1.1.1. Сохранение одного заголовка в 1.1.2 оставляет этот исходный формат; старый редактор не получает новую поддержку такого входа. Совместимость проверена для исходных валидных блоков 1.1.1 и для HTML-only fixtures после полной сериализации Gutenberg. Повторное редактирование в 1.1.1 возвращает его прежние ошибки, которые эта версия 1.1.2 исправляет.

## Нативный LocalWP, журналы и границы

Условия Local принял сам пользователь. До создания стенда существующих сайтов Local не было. Создан только `SDCW-112-Isolated-20261028`, ID `ujo3kaSGV`, `http://localhost:10003`, внутри `.local/native-local-sites/`. Почта и внешний HTTP WordPress заблокированы. Тестовые PHP-копии отличаются от Docker-источников только абсолютным путём fixtures; все утверждения идентичны, их хеши сохранены.

Один первый baseline editor load на официальном 1.1.1 превысил 20 секунд; повторная диагностика загрузилась за 0,8 секунды. Позже один одновременный Firefox login превысил 20 секунд; отдельный повтор прошёл. Для итоговых native reader runs входы одними аккаунтами выполнялись последовательно и прошли. Эти таймауты сохранены; их причина не установлена и не приписывается плагину. В журналах нет новых PHP warnings/fatals из файлов плагина. Предупреждения Core о запрещённых внешних update checks, связанный с WP_DEBUG_DISPLAY каскад headers-already-sent на прежних Docker-стендах, PHP 8.5 notices в WP-CLI vendors и исправленные ошибки вспомогательных eval-команд отделены от продуктовых ошибок.

Native HTTPS/Site Domains, native multisite и произвольные сторонние расширения не покрыты. Subdirectory multisite проверен в Docker; subdomain-сеть не проверена. Причина исходного публичного отзыва остаётся неизвестной. Предыдущие standalone lint/22 Node/84 browser результаты не выдаются за новый запуск; исходники и bundle 0.7.0 неизменны, bundle SHA-256 `1ac6a8d90de417b73afa8e9c93de9603313f7c423c93ad051b87f820f891d368`.

После приёмки восстановлен окончательный ZIP, остановлены только собственные Docker-стенды и единственный native Local сайт. БД, образы и evidence сохранены. Путь будущих Local-сайтов возвращён в `~/Local Sites`; тестовый сайт остаётся внутри репозитория. Local CLI установлен, Router mode оставлен `localhost` для воспроизводимого стенда.
