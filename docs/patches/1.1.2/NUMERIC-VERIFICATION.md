## Исправление и воспроизведение до правки

Прежний ZIP `4c62efe3…` и его исходники сохранены отдельно. Новый PHP-набор до изменения продукта дал **1678/1840**, с 162 отрицательными утверждениями на четырёх конфигурациях. Он проверяет 27 случаев через реальные post updates, включая `post_content`, `post_excerpt`, `post_content_filtered`, исходный JSON, безопасность и повторное сохранение.

Нативный набор предыдущего ревью давал **86/96** блоков: на WP 6.3/6.8 терялся буквальный уровень `&amp;#…;`, на WP 7.1 числовой CR менялся на LF. Тот же набор после исправления проходит **96/96**, с валидным настоящим редактором.

Относительно `4c62efe3…` изменён один файл продукта: [`includes/simple-digital-clock-kses.php`](../../../wordpress/simple-digital-clock/includes/simple-digital-clock-kses.php). Поправка локальна для `caption` часов в стандартном Core save pipeline:

- Перед KSES буквальный амперсанд перед numeric syntax защищается числовым `&#38;`. Старый Core больше не раскрывает следующий numeric reference. Сохраняются decimal/hex, ведущие нули, верхний регистр и несколько буквальных уровней.
- Сырые CR/CRLF до KSES нормализуются в LF, как при исходном HTML-разборе. Numeric CR на этом этапе остаётся reference.
- CR, который Core 7.1 сериализует после декодирования numeric reference, снова кодируется числовым reference в `wp_insert_post_data`. ASCII guard учитывает CR. Поэтому raw CR и numeric CR сохраняют разные исходные DOM-значения.

Именованные HTML5 entities, обратные косые черты и `utf8mb3` продолжают работать. JSON caption сохраняет исходную строку. Неизвестные метаданные и соседние блоки проходят прежнюю фильтрацию; опасные атрибуты удаляются KSES. Глобальная политика KSES, общий сериализатор WordPress и standalone-виджет 0.7.0 не менялись. Миграции БД и массового переписывания старых записей нет.

## Коррекция одного прежнего тестового эталона

В `final-review.php` одно ожидание вычислялось через `wp_kses_normalize_entities($html)`. Для двойного экранирования numeric references на WP 6.3/6.8 оно тем самым ожидало тот же дефект Core, который требуется исправить.

Эталон заменён на исходное DOM-значение fixture: этот fixture явно экранирует каждый амперсанд через `htmlspecialchars(..., true)`, поэтому после одного HTML-декодирования ожидается исходная строка caption. Число и строгость утверждений сохранены. Контроль обычного соседнего HTML по-прежнему использует стандартный KSES.

Исправленный эталон отдельно запущен с точным прежним PHP-кодом `4c62efe3…`: **590/592**, по одному воспроизведению на WP 6.3/6.8. С исправлением — **592/592**. Независимые браузерные ожидания исходных fixtures не менялись; расширенный набор берёт DOM-эталон из валидного оригинала 1.1.1.
