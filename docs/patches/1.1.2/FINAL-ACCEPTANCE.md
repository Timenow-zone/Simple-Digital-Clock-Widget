## Критерий совместимости

Замена файлов должна сохранять все существующие строки таблиц posts, настройки `widget_*`, `sidebars_widgets`, `theme_mods_*` и активацию плагина. Чтение старой записи в другом browser timezone должно открывать валидные блоки без dirty state. После сохранения должны оставаться прежними значения настроек, смысл подписей, DOM часов, соседние блоки и расположение виджетов.

Для отображения сравниваются атрибуты, текст при фиксированном времени, размеры custom element и основные computed styles часов: цвета, фон/градиент, рамка, скругление, тень, шрифт, выравнивание и transform. Допуск геометрии — **0,001 CSS px**; текст, атрибуты и значения стилей сравниваются точно. Это проверка перечисленных метрик, а не попиксельное сравнение скриншотов.

## Обновление, откат и сохранность данных

Публичный исходный релиз — [1.1.1](https://wordpress.org/plugins/simple-digital-clock/). На всех девяти установках физически установлен его официальный ZIP; сверены все 14 файлов. Контрольные записи созданы именно на нём, а не синтезированы только новым сериализатором.

Обновление выполнялось **`Plugin_Upgrader::bulk_upgrade()` с `WP_Ajax_Upgrader_Skin`** — это путь, который использует `wp_ajax_update_plugin`. Предложение обновления и пакет локальные; прежний `update_plugins` transient восстанавливается. WordPress сам распаковывает ZIP, заменяет каталог и выполняет свои update hooks. Это проверка механизма обновления, а не доставки ещё не опубликованной версии через WordPress.org.

Первое обновление сохранило побайтно все **19 399 строк posts** и все проверяемые настройки/активацию. После чтения старые строки также не изменились. Core создал 22 пустых auto-draft для новых тестовых пользователей и переиндексировал целочисленные ключи массивов inactive widgets в четырёх контекстах; значения, принадлежность sidebar и порядок виджетов сохранились. Эти отличия отдельно зафиксированы, полное равенство всей БД после входа в админку не заявляется.

Затем одни и те же ID прошли title-only, полное и повторное сохранение в трёх движках. JSON может получить явный `timeZone`, восстановленный из старого HTML. Это фиксация существующего значения при сохранении, не изменение часового пояса и не фоновая миграция. Старые виджеты не удаляются и не создаются заново.

После этих сохранений физически возвращён официальный ZIP 1.1.1; сверены его 14 файлов. **21 656 строк posts** и настройки на замене файлов побайтно прежние. БД не восстанавливалась. Старые редактор и frontend прочитали подготовленные данные в трёх движках; ни блоки, ни подписи, ни проверенные настройки/расположение виджетов не потеряны. Чтение после отката не изменило существующих строк, widget contents, настройки и порядок sidebar.

Отдельно подтверждено: все **19 314 строк posts, существовавшие до начала этой приёмки**, сохранились целиком, включая поля помимо post_content. Новые тестовые записи учитываются отдельно.

После отката повторно выполнено штатное обновление на тот же ZIP 1.1.2. Все 15 файлов сверены на девяти установках, снимки данных до/после замены совпали побайтно. Заключительные чтения, mobile/tablet smoke и сверка настроек прошли; после чтения данные также неизменны. БД ни на одном переходе не восстанавливалась.

На стендах оставлен кандидат 1.1.2. Оба выделенных Compose-проекта и отдельный Firefox server остановлены; native-сайт имеет статус `halted`. Базы, исходные снимки и результаты сохранены.

Откат проверяет чтение и отображение подготовленных данных. Повторное редактирование на 1.1.1 возвращает её известные ограничения KSES/Author и старый UI; исправность старой версии при таких новых правках не обещается. Обновление также не восстанавливает автоматически HTML, уже удалённый прежним сохранением на 1.1.1.

## Ограничения и неудачные попытки

- Мышиный Reset → Auto language в headless WebKit/Firefox остаётся нестабилен. В новом контроле подставлен **точный публичный 1.1.1 block.js**, SHA-256 `1ce3df3a6aa541f09b5bb34a8f27e41582b417f3a309154d1eea6645d78f5eda`, только в HTTP-ответ браузера. По два реально перехваченных ответа на движок. После гарантированного очищения мышиный Auto оставляет пустую строку и на публичном JS, и на кандидате; клавиатура возвращает `en-US`. Это подтверждает прежний характер данного headless-сценария; причина смены цели событий и обычные Safari/Firefox пользователя не установлены. Это не новый дефект Locale и не доказательство всех мышиных путей.
- В первом Firefox Locale-прогоне WP 6.3 был timeout ожидания вставки блока на Author, без JS-исключений. Повтор без изменения продукта прошёл 42/42. Причина единичного timeout не установлена; неудачный файл сохранён.
- Первое сравнение геометрии Firefox после смены заголовка выявило только разницу DOMRect **0,0000152587890625 px** в высоте. Все прочие метрики совпали. Данные сохранены; введён явный допуск 0,001 px и сценарии пересохранения повторены успешно.
- Исправлены ошибки setup теста: Core 7 помечает атрибут HTML block как local, поэтому сохранённый HTML создаётся через parse; новые widget instances сначала размещаются, затем проверяется фактический sidebar; некорректный self-link template-part Core 6.3 заменён в тестовом запросе на theme//slug. Исходные неудачные JSON не перезаписаны.
- Первый низкоуровневый `upgrade()` в CLI заменил файлы, но оставил реактивацию браузерному skin. Стенд восстановлен на активный 1.1.1, тест переведён на фактический AJAX-путь Core `bulk_upgrade()`. Это изменение теста, не исправление плагина.
- PHP-журналы не подавлялись. В отслеживаемых хвостах есть предупреждения Core о заблокированных внешних update requests и deprecation WP-CLI Colors на PHP 8.5. Они классифицированы в evidence; чистые журналы целиком не заявляются.

Не покрыты произвольные сторонние темы/плагины, subdomain multisite, Native HTTPS/Site Domains, ручная системная IME, браузер и сайт автора отзыва. Визуальные сравнения используют одинаковый набор локальных/fallback fonts; внешние запросы браузера блокируются, доставка Google Fonts не проверяется. Причина конкретной жалобы LocalWP по-прежнему неизвестна.

## Воспроизведение

Нужен уже подготовленный изолированный lab и текущие конфигурации/credentials в `.local/`. Последовательные команды, фактические labels, снимки и проверки перед/после замены файлов сохранены в `final-acceptance-921/accept.py`, `matrix.py`, `compare_reads.py` и JSON evidence. Новые результаты защищены от перезаписи; для ручного повторного read smoke нужен свежий stage:

```bash
set -euo pipefail
node tools/wordpress-lab/final-acceptance.mjs check "manual-$(date +%Y%m%d-%H%M%S)" chromium localwp
```

Команда требует запущенного именно этого native lab с кандидатом. Не переключать версии плагина параллельно browser runs. Для остановки используются только два выделенных Compose-проекта, отдельный Firefox server и созданный native-сайт; данные и evidence сохраняются.
