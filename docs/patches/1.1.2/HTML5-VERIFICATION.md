## Воспроизведение и изменение

Прежний кандидат `4f5b285c…` портил HTML-подпись `&NotEqualTilde; <clock>` при сохранении Author, включая изменение одного заголовка: браузер получал буквальное имя entity, блок становился невалидным. Стандартный KSES нормализует entities до `pre_kses`, поэтому изменение приоритета внутри прежнего обработчика не решает потерю исходного смысла.

До изменения продукта независимый набор из 46 нативных подписей дал **1380/1496**, с 116 отрицательными утверждениями. Полный набор из 8500 HTML5-вариантов дал **14976 несовпадений DOM** на четырёх конфигурациях. Эти исходные результаты сохранены; ожидания полного набора не менялись.

Относительно `4f5b285c…` изменён один файл продукта: [`includes/simple-digital-clock-kses.php`](../../../wordpress/simple-digital-clock/includes/simple-digital-clock-kses.php).

- В стандартных `content_save_pre`, `excerpt_save_pre`, `content_filtered_save_pre` на приоритете 8 обрабатывается только атрибут `caption` часов и только при установленном `wp_filter_post_kses`.
- Неподдерживаемые KSES именованные HTML5 references преобразуются в числовые до потери исходного значения. Один проход сохраняет различие `&Name;`, `&amp;Name;`, `&amp;amp;Name;`. Положение атрибута определяет нативный lexer WordPress.
- Обратная косая черта защищена от изменения при повторном KSES-save. Числовое представление Unicode повторно закрепляется в `wp_insert_post_data`, поскольку новый Core может снова сериализовать его как Unicode.
- Это позволяет сохранять ASCII-entities с символами вне BMP на старых колонках `utf8mb3`. Промежуточный вариант, выдававший Unicode для `&Afr;`, эту проверку действительно провалил; окончательный ZIP проходит её. Существующие C1 controls сохраняются без HTML5 numeric remapping.

Исходный текст caption в JSON, объектные типы неизвестных метаданных и соседние блоки сохраняются. KSES продолжает удалять опасные HTML-атрибуты и неизвестные опасные JSON-значения. Глобальные правила KSES и экранирования атрибутов не расширяются. Формат 1.1.1 остаётся читаемым; массовой миграции БД нет. Bundle standalone-виджета 0.7.0 не менялся.

Откат возвращает исходные ошибки редактирования 1.1.1; проверка подтверждает совместимость хранения новых сохранений со старым читателем.

## Среда и границы проверки

Chromium 151.0.7922.34 и WebKit 26.5 запускались на macOS arm64; Firefox 153.0 — в официальном `mcr.microsoft.com/playwright:v1.62.1-noble`, через loopback WebSocket. Версии клиента и образа совпадают. Использован [поддерживаемый remote server Playwright](https://playwright.dev/docs/docker), с [ограниченным loopback-туннелем](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-option-expose-network).

Нативный Firefox на этом Mac перестал запускаться до выполнения утверждений; проверки повторены в указанном контейнере без отключения системной защиты. Попытка запустить WTR внутри Linux с macOS `node_modules` остановилась на отсутствующем platform-пакете Rollup; успешный WTR-run использует host dependencies и тот же удалённый Firefox. Тестовые утверждения не менялись.

Один промежуточный browser-run ошибочно пересёкся с установкой baseline. Его результаты исключены из приёмки. Окончательный цикл выполнен последовательно с проверкой файлов после каждой установки; промежуточные ZIP, неудачные логи и повторные запуски сохранены отдельно.

Отдельный контроль на точном 1.1.1 подтвердил существующее ограничение сериализатора Core 6.3/6.8: сырой завершающий `\` может породить невалидный JSON ещё до фильтров плагина. Новые fixtures проверяются на валидность до сохранения; завершающая косая черта представлена валидным `&bsol;`. Неизвестные JSON-ключи/значения с внутренними `\` проходят. Общий сериализатор WordPress этот патч не меняет.

Проверены стандартные Core save pipelines. Нативный LocalWP, multisite, runtime PHP 7.x/8.5 и конкретные сторонние плагины/темы не проверялись; локальный PHP 8.5 использован только для syntax checks. Причина исходного пользовательского отзыва остаётся неизвестной. В проверенных сценариях новых регрессий и нарушений обратной совместимости не обнаружено; это не универсальная гарантия для стороннего кода.
