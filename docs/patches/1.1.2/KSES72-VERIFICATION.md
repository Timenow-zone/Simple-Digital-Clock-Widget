# KSES в WordPress 7.2 Beta 2 — исправление 1.1.2

29 октября 2026. **P2 исправлен; функциональный ZIP принят в проверенной локальной матрице. Новых регрессий в ней не обнаружено. Публикаций нет.** [Машиночитаемые результаты и SHA-256 доказательств](kses72-evidence.json).

Последующая [синхронизация POT и упаковки](../../releases/1.1.2/METADATA-SYNC.md) изменила только метаданные переводов. Этот отчёт и его evidence сохраняют идентичность функционального ZIP `6f896d42…`; текущий установочный SHA указан в release manifest.

## Дефект и воспроизведение

[Первичная диагностика](WP-7.2-BETA.md) относится к предыдущему ZIP `1e5d3f0d…`. В WP 7.2 Beta 2 новый HTML API KSES обрабатывает JSON блока после `pre_kses`. Прежнее восстановление подписи в `pre_kses` срабатывало слишком рано: при сохранении Author JSON-подпись изменялась, а HTML-атрибут сохранял прежний текст. Даже изменение одного заголовка делало блок невалидным после перезагрузки редактора.

Перед исправлением новые тесты дали **27 ошибок из 132 на каждом из двух beta-сайтов**. Реальная кнопка Save воспроизводила дефект во всех трёх движках. Неуспешные результаты сохранены в `.local/wordpress-lab/kses72-fix/red/` и прежнем evidence; они не перезаписывались.

## Изменение

Относительно предыдущего подготовленного патча изменены два установочных файла:

- `includes/simple-digital-clock-kses.php`: защита plain-text JSON-подписи действует до завершения штатного KSES; восстановление выполняется после его возврата.
- `readme.txt`: добавлена строка changelog. Исходные CRLF сохранены.

Каждому собственному вызову сохранения соответствует отдельный стек и временные UUID-маркеры. Защищается только строковая `caption` полного известного блока часов. Настоящий HTML, обработчики событий и остальные JSON-поля проходят текущую политику Core. `serialize_block_attributes()` безопасно экранирует восстановленный JSON. Маркеры не сохраняются в БД.

Слешированные фильтры записи (`content_save_pre`, `excerpt_save_pre`, `content_filtered_save_pre`) и отдельная санитизация block widget используют независимые области. Ограниченный `debug_backtrace` читает только имена функций и идентичность объекта `WP_Hook`, без аргументов: он отличает зарегистрированный Core callback от постороннего KSES, вызванного соседним фильтром. Проверены вложенные прямые, слешированные и сторонние hook-вызовы, ранние и поздние политики. Без этой проверки промежуточные варианты ошибочно перехватывали чужую санитизацию; они отклонены.

Новый HTML API KSES остаётся включён. Глобального переключения на legacy parser нет. Прямой чужой `wp_kses_post()` следует политике Core; сохранение подписей плагина проверяется через реальные фильтры записей, собственный sanitizer и публичный callback виджета.

`block.js`, схема атрибутов, `save()`, CSS и runtime 0.7.0 в этом исправлении не менялись. Миграции БД, новых настроек и нового формата хранения нет.

## Приёмка

ZIP функциональной приёмки: `6f896d42797e6d3a4727f8ece6d13bb8f4be2ed8e9425473ef02ea5e374d8720`, 15 файлов. Официальная 1.1.1: `b6afe710826e74370889773f0fb600a89614a18058b4f264ca12fc7df4f97c10`, 14 файлов.

Матрица включает 11 установок / 12 контекстов: WP 6.3.2, 6.8.3, 7.1.3 и **7.2 Beta 2**; PHP 7.0, 7.4, 8.2, 8.3, 8.4 и 8.5; одиночные сайты, multisite root/child и настоящий LocalWP. Beta проверена на PHP 8.3.35 и 8.5.12 с неизменённым официальным Core и включённым новым KSES. Точные версии и темы записаны в evidence.

Окончательный ZIP проходит **18 336/18 336 PHP-проверок**: 13 наборов на контекст, включая прежние 11 наборов и 176 новых проверок на контекст. Проверены заголовок без изменения содержимого, полное и повторное сохранение, три поля записи, HTML5/числовые entities, небезопасные соседние JSON-поля, XSS-атрибуты, вложенные фильтры и сохранение ранее применённых политик. Все **1 309 248 DOM-сравнений** в Chromium, Firefox и WebKit сохраняют значение entities.

Свежие фикстуры созданы официальной 1.1.1. Проверяется штатный Core updater, чтение старых блоков, пересохранение 1.1.2 разными ролями, активные/неактивные block widgets, паттерны, template parts и соседние Core-блоки. Физический откат выполняется поверх пересохранённых данных; БД не восстанавливается. Полные строки posts хешируются по всем колонкам, настройки виджетов, сайдбаров, тем, URL и активации сравниваются точно до/после замены файлов.

При первом штатном обновлении побайтно сохранены все **31 426** полных строк posts; при откате и повторном обновлении — **34 468**, включая созданные тестами записи. Настройки widget/sidebar/theme/URL/activation также не изменились от замены файлов. Число строк увеличилось только за счёт самих тестовых записей и ревизий; миграций и восстановления БД не было.

Native HTTPS повторён через **собственный loopback listener 19443** того же нативного nginx Local, PHP-FPM и MySQL. Общий router Local оставлен в режиме localhost, поскольку в Local уже зарегистрированы другие тестовые сайты. Конфигурация router и исходная конфигурация сайта совпали по SHA-256 до/после проверки; доверие сертификатам не менялось. Это проверка нативного TLS на отдельном порту; новый прогон Site Domains/443 и обычного приложения Safari не заявляется.

## Инструменты и границы

Новые PHP-наборы: `tools/wordpress-lab/kses72-regression.php`, `kses72-owned-pass.php`. `kses72-widget-rest.mjs` проверяет реальный HTTP REST-сценарий фильтруемого пользователя, сохранение активного/неактивного виджета и frontend sidebar. `beta72-ui.mjs` проверяет настоящую кнопку Save и повторное открытие блока.

Приёмочные сценарии и полные доказательства находятся в `.local/wordpress-lab/kses72-final/`. Основные команды для уже подготовленных стендов сохранены в `cycle.py`, `php.py`, `browser.py`, `dom.py`, `finish-cycle.py`, `integrations/run.py`, `native-https/run.py`. Они не предназначены для пользовательских сайтов; существующие evidence не перезаписываются. Проверки сохраняют временные тестовые записи в своих БД. После приёмки собственные Docker-стенды, временный Firefox и свой сайт Local остановлены; все 14 тестовых loopback-портов закрыты. Базы и volumes сохранены, другие Local-сайты не менялись.

Два исходных browser-прогона остановились до проверок Locale при клике по перерисовываемому inserter. Проверка использует точную доступную option и клавиатурное подтверждение; мышиные Auto/Reset отдельно проверяются прежним набором. Повторы сохраняют отдельные имена. В интеграционном тесте явно подтверждается cache HIT перед сохранением виджета; корректный свежий ответ не считается ошибкой. При устаревшем HIT применяется ранее подтверждённая независимым Core Paragraph политика ручной очистки кеша. Браузерные драйверы ждут готовности редактора и canvas; глобальный network-idle не используется как признак готовности.

WP 7.2 остаётся beta: принят конкретный Beta 2, окончательная версия ещё не проверена. `Tested up to: 7.1` сохранён. Кастомные сторонние политики KSES на приоритете `PHP_INT_MAX` после нашей защиты и произвольные сторонние интеграции отдельно не сертифицированы. Google Fonts/CDN заблокированы в изолированных браузерных прогонах. Публичная доставка WordPress.org и сайт автора отзыва не проверялись.

Откат ZIP не восстанавливает данные, испорченные прежними версиями до исправления. Повторное редактирование уже под 1.1.1 снова подвержено её известным дефектам. Для отмены самого изменения доступны прежний Git-коммит, ZIP `1e5d3f0d…`, исходники и подготовка SVN; полный diff от официальной 1.1.1 проверяется отдельным применением к её чистой копии.
